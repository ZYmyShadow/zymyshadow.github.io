Introduction

Logback is the built-in logging framework of Spring Boot. In day-to-day Spring Boot usage, this is the framework being used — it outputs logs directly to the console but does not write them to log files. When deploying to a server, developers or operations staff can't possibly watch the project on the server all day, so logs need to be written to files for later review. Logback has this capability.

You might ask, why not use log4j? As a developer, the leaner the project, the faster and more stable it runs. Since Spring Boot comes with a built-in logging framework, it makes sense to use it.

Spring Boot Default Logging Configuration

The behavior of loggers (Logger) is hierarchical. Log levels from low to high are: TRACE < DEBUG < INFO < WARN < ERROR < FATAL. If set to WARN, logs below the WARN level will not be output.

By default, Spring Boot uses logback as its system logging implementation framework, outputting logs to the console without writing to log files. The log level printed to the console by Spring Boot defaults to INFO and above. The log level can be modified in application.properties with logging.level.root=WARN.

As shown in the image above, the log output contains the following elements:

  • Timestamp: precise to milliseconds
  • Log level: ERROR, WARN, INFO, DEBUG, TRACE
  • Process ID: PID
  • Separator: --- marks the start of the actual log message
  • Thread name: enclosed in brackets (may be truncated in console output)
  • Logger name: typically the source code class name
  • Log message:

Spring Boot Startup Order

logback-spring.xml -> application.properties or application.yml -> logback.xml

Therefore, it is recommended to create a custom logback-spring.xml file.

Spring Boot Custom logback-spring.xml Configuration

Create a logback-spring.xml file under src/main/resources to separately record system output logs and Error logs:

<?xml version="1.0" encoding="UTF-8" ?>
<configuration>
    <!-- Fix %clr not being recognized -->
    <include resource="org/springframework/boot/logging/logback/defaults.xml"/>
    <!-- Color log output format -->
    <property name="CONSOLE_LOG_PATTERN" value="%clr(%d{yyyy-MM-dd HH:mm:ss.SSS}){faint} %clr(%level){blue} %clr(${PID}){magenta} %clr([%thread]){orange} %clr(%logger){cyan} %m%n${LOG_EXCEPTION_CONVERSION_WORD:-%wEx}" />
    <!-- Non-color log output format -->
    <property name="PATTERN" value="%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n"/>

    <!-- Debug file path: logs directory at the same level as src; parent directories are auto-created if they don't exist -->
    <property name="DEBUG_FILE_PATH" value="./logs/debug" />
    <!-- Release file path -->
    <property name="RELEASE_FILE_PATH" value="./logs/release" />

    <!-- Console output -->
    <appender name="consoleAppender" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>${CONSOLE_LOG_PATTERN}</pattern>
        </encoder>
    </appender>

    <!-- Generate output log files daily -->
    <appender name="fileAppender" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
        <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
            <fileNamePattern>${DEBUG_FILE_PATH}/output-%d{yyyy-MM-dd}.%i.log</fileNamePattern>
            <maxFileSize>5MB</maxFileSize>
            <maxHistory>30</maxHistory>
            <totalSizeCap>1GB</totalSizeCap>
        </rollingPolicy>
    </appender>

    <!-- Generate error log files daily -->
    <appender name="errorAppender" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <filter class="ch.qos.logback.classic.filter.ThresholdFilter">
            <level>ERROR</level>
        </filter>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
        <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
            <fileNamePattern>${DEBUG_FILE_PATH}/error-%d{yyyy-MM-dd}.%i.log</fileNamePattern>
            <maxFileSize>5MB</maxFileSize>
            <maxHistory>30</maxHistory>
            <totalSizeCap>1GB</totalSizeCap>
        </rollingPolicy>
    </appender>

    <!-- Development environment: print to console -->
    <springProfile name="debug">
        <logger name="com.hzhazha" level="debug" />
        <root level="INFO">
            <appender-ref ref="consoleAppender" />
            <appender-ref ref="fileAppender" />
            <appender-ref ref="errorAppender" />
        </root>
    </springProfile>

    <!-- Production environment: output to file -->
    <springProfile name="release">
        <root level="INFO">
            <appender-ref ref="releaseConsoleAppender" />
            <appender-ref ref="releaseFileAppender" />
            <appender-ref ref="releaseErrorAppender" />
        </root>
    </springProfile>
</configuration>

Then add spring.profiles.active=debug/release in the application.properties file to use the corresponding configuration.

This separates the debug environment from the development environment. I've only done a simple configuration here; for detailed configuration, please refer to the official documentation.

logback-spring.xml File Explanation

First, you need a root element configuration. If you add scan="true" to the element, the configuration file will be automatically reloaded after modifications.

Writing the XML file is like writing Java files — the include tag imports packages, and property sets variables.

The Most Important Part: Appender

This is for configuring console output, file output, or log output at a specified level, etc.

Configuration ParameterDescription
ConsoleAppenderOutput to console
FileAppenderOutput to file
RollingFileAppenderExtends FileAppender, supports rolling log files
ThresholdFilterLog level filter
SizeAndTimeBasedRollingPolicyRolling based on size and time (recommended)

After Configuring All Appenders, Write the Configuration Calls in logback-spring.xml

Use the springProfile element to link with spring.profiles.active=debug/release in the configuration file, so that the specific configuration from that profile is used.

spring.profiles.active=debug

<springProfile name="debug">
  <root level="INFO">
    <appender-ref ref="consoleAppender" />
    <appender-ref ref="fileAppender" />
    <appender-ref ref="errorAppender" />
  </root>
</springProfile>

Once the above configuration is complete, you can start the project.
