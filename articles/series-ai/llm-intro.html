大语言模型入门指南

入门
概要：本文面向零基础读者，系统梳理大语言模型（LLM）的核心概念、技术架构、发展历程与主流模型对比。从「什么是 LLM」出发，逐步深入到 Transformer 架构、训练流程、Token 机制等关键技术概念，最后对 GPT、LLaMA、Qwen、Mistral 等主流模型进行横向对比。文中涉及的技术概念均配有通俗解释，适合希望建立完整 LLM 知识框架的初学者。部分前沿内容（如 MoE 架构细节）因技术仍在快速演进中，结论可能存在时效性。

什么是大语言模型

大语言模型（Large Language Model, LLM）是一种基于深度学习的自然语言处理模型，其核心能力是理解和生成人类语言。它通过分析海量文本数据中的统计规律，学会预测「下一个最可能出现的词」，从而能够完成对话、写作、翻译、编程等多种任务。

理解 LLM 的关键在于把握三个要素：

  • 「大」——参数量巨大，通常在数十亿（Billion）到数万亿级别。参数是模型从训练数据中学到的「知识」的载体，参数越多，模型的表达能力越强
  • 「语言」——以自然语言（文本）为主要输入和输出形式。虽然现代 LLM 已扩展到多模态（图像、音频），但语言仍是核心
  • 「模型」——本质上是一个巨大的数学函数，输入一段文本（编码为数字），输出另一段文本（解码为人类可读的文字）
通俗理解：可以把 LLM 想象成一个「超级 autocomplete（自动补全）」。当你输入"今天天气真"，它会预测下一个字最可能是"好"。但因为它在训练时「阅读」了互联网上几乎所有的文本，所以它的补全能力远超简单的词汇联想——它能理解上下文、推理逻辑、模仿风格，甚至写出有创意的内容。

核心概念解析

Token 与 Tokenizer

Token是 LLM 处理文本的基本单位。模型不直接处理「字」或「词」，而是将文本切分为 token 序列。

概念 说明 示例
Token 模型处理的最小文本单元，可以是字、词、子词或标点 "Hello world" → ["Hello", " world"]（2 个 token）
Tokenizer 将文本切分为 token 的算法，不同模型使用不同的 Tokenizer GPT 使用 BPE，LLaMA 使用 SentencePiece
Token 与字的关系 英文约 1 token ≈ 4 字符 ≈ 0.75 词；中文约 1-2 字 ≈ 1 token "大语言模型" → 约 4-6 个 token（取决于 Tokenizer）
Vocabulary Size Tokenizer 的词表大小，即所有可能 token 的总数 GPT-4 约 100K，LLaMA 3 约 128K，Qwen2.5 约 152K

Token 的概念之所以重要，是因为：模型的上下文窗口、推理速度、API 计费都以 token 为单位。理解 token 有助于你更好地评估模型的成本和性能。例如，GPT-4o 的上下文窗口是 128K tokens，约可容纳 6-8 万汉字或 10 万英文单词。

参数（Parameter）

参数是模型在训练过程中学到的数值（权重和偏置），决定了模型如何从输入映射到输出。参数量是衡量模型规模的核心指标。

参数规模 代表模型 能力水平 显存需求（FP16）
1-3B Qwen2.5-3B、Phi-3-mini 简单对话、基础问答 ~3-6 GB
7-9B LLaMA 3-8B、Qwen2.5-7B、Gemma 2-9B 流畅对话、代码辅助、摘要 ~14-18 GB
14-32B Qwen2.5-14B/32B、Mistral-Nemo 复杂推理、长文写作、分析 ~28-64 GB
70-72B LLaMA 3.1-70B、Qwen2.5-72B 接近 GPT-3.5 水平 ~140 GB
405B+ LLaMA 3.1-405B、GPT-4（未公开） 旗舰级，接近人类专家 ~800 GB+（需多卡）
重要认知：参数量不是越大越好。在特定任务上，经过高质量数据训练的较小模型可能优于参数量更大但训练数据质量较差的模型。例如，Qwen2.5-7B 在很多中文任务上的表现优于参数量更大的 LLaMA 3-70B，这是因为 Qwen 使用了更多高质量的中文训练数据。选择模型时应综合考虑参数量、训练数据质量和任务匹配度。

上下文窗口（Context Window）

上下文窗口是模型一次能处理的最大 token 数量，包括输入（prompt）和输出（response）的总和。它决定了模型能「看到」多少信息。

上下文窗口的意义在于：

  • 窗口越大，模型能处理的文档越长，多轮对话的历史越完整
  • 但窗口越大，推理时的显存占用越高（KV Cache 随上下文长度线性增长）
  • 窗口大小不等于有效注意力范围——模型对上下文中间部分的信息关注度较低（"Lost in the Middle" 现象）

温度（Temperature）与采样

温度是控制模型输出随机性的关键参数：

温度值 效果 适用场景
0.0 - 0.3 高度确定性，几乎总是选择概率最高的 token 代码生成、事实问答、数据提取
0.4 - 0.7 适度随机，在准确性和多样性之间平衡 通用对话、写作辅助
0.8 - 1.2 较高随机性，输出更多样化 创意写作、头脑风暴
1.5 - 2.0 高度随机，可能产生不连贯或荒谬的内容 实验性用途，一般不推荐

Transformer 架构

Transformer 是所有现代 LLM 的基础架构，由 Google 在 2017 年的论文 "Attention Is All You Need" 中提出。理解 Transformer 的核心机制有助于理解 LLM 的能力和局限。

架构演进

时期 架构 代表模型 特点
2017 之前 RNN / LSTM / GRU Seq2Seq、ELMo 顺序处理，无法并行，长距离依赖捕捉困难
2017 Transformer（原始） — 自注意力机制，完全并行，但计算复杂度为 O(n²)
2018-2020 Encoder-only / Decoder-only BERT / GPT-2 分化出理解型（Encoder）和生成型（Decoder）两大路线
2020-2023 Decoder-only + 规模化 GPT-3、PaLM、LLaMA 纯 Decoder 架构成为主流，参数量急剧增长
2023-2026 MoE + 多模态 + 长上下文 Mixtral、GPT-4o、Qwen2.5 混合专家、视觉/音频理解、百万级上下文窗口

自注意力机制（Self-Attention）

自注意力是 Transformer 的核心创新。它允许模型在处理每个 token 时，「关注」输入序列中的所有其他 token，从而捕捉长距离的语义关联。

通俗理解：当你阅读句子"小明把球踢给了小红，她很高兴"时，你会自动将"她"与"小红"关联起来。自注意力机制让模型也能做类似的事情——在处理"她"这个 token 时，模型会计算它与句子中所有其他 token 的关联度，发现"她"与"小红"的关联最强，从而正确理解指代关系。

自注意力的计算过程涉及三个关键矩阵：

  • Query（查询）——当前 token 想要寻找什么信息
  • Key（键）——每个 token 能提供什么信息
  • Value（值）——每个 token 实际携带的信息内容

通过计算 Query 和 Key 的相似度（点积），模型得到注意力权重，然后用这些权重对 Value 进行加权求和，得到当前 token 的上下文感知表示。

Decoder-only 架构

当前主流 LLM（GPT 系列、LLaMA、Qwen、Mistral 等）均采用 Decoder-only 架构。其核心特点是：

  • 因果注意力（Causal Attention）——每个 token 只能关注它之前的 token，不能看到未来的 token。这确保了模型只能基于已有信息生成下一个 token，符合自回归生成的逻辑
  • 自回归生成（Autoregressive Generation）——逐 token 生成，每次生成一个 token 后将其加入上下文，再生成下一个。这也是 LLM 推理速度受限的根本原因——无法并行生成
  • 位置编码（Positional Encoding）——由于 Transformer 本身不感知 token 的顺序，需要通过位置编码注入位置信息。现代模型多使用 RoPE（旋转位置编码），支持长度外推（训练时未见过的更长序列）
知识延伸：为什么 Decoder-only 成为了主流？早期的 Transformer 有 Encoder（理解）和 Decoder（生成）两部分。BERT 使用 Encoder-only 擅长理解任务（分类、提取），GPT 使用 Decoder-only 擅长生成任务。研究发现，当模型规模足够大时，Decoder-only 架构在理解和生成任务上都能表现优秀（涌现能力），且架构更简单、训练更高效。因此，2023 年之后的新模型几乎全部采用 Decoder-only 架构。

训练流程

LLM 的训练通常分为三个阶段，每个阶段的目标和方法各不相同。

预训练（Pre-training）

预训练是让模型在海量无标注文本上学习语言规律的过程，也是成本最高的阶段。

要素 说明
训练数据 互联网文本（网页、书籍、论文、代码等），通常数万亿 token
训练目标 下一个 token 预测（Next Token Prediction）——给定前面的 token，预测下一个 token
计算资源 数千到数万块 GPU，训练数周到数月
成本估算 GPT-4 级别约 $50M-$100M+；LLaMA 3-70B 约 $2M-$5M
产出 Base Model（基座模型）——能续写文本但不会对话、不遵循指令

指令微调（SFT, Supervised Fine-Tuning）

指令微调是让模型学会遵循指令、以对话形式交互的阶段。

  • 使用人工标注的「指令-回答」配对数据（通常数万到数十万条）
  • 训练目标从「预测下一个 token」变为「生成符合指令要求的回答」
  • 经过 SFT 的模型被称为 Instruct/Chat 模型，可以进行多轮对话
  • 成本远低于预训练，通常在数百块 GPU 上训练数天

人类反馈强化学习（RLHF）

RLHF（Reinforcement Learning from Human Feedback）是进一步提升模型输出质量的可选阶段，主要用于闭源模型（如 GPT-4、Claude）。

  • 让人类标注员对模型的多个回答进行排序（哪个更好）
  • 训练一个奖励模型（Reward Model）来模拟人类偏好
  • 用强化学习（通常是 PPO 算法）优化模型，使其输出更受人类偏好
  • RLHF 可以显著改善模型的安全性、有用性和诚实性
  • 开源社区也有替代方案，如 DPO（Direct Preference Optimization），无需单独训练奖励模型
开源 vs 闭源的训练差异：闭源模型（GPT-4、Claude）通常经过完整的三阶段训练 + 大量 RLHF，输出质量高但训练细节不公开。开源模型（LLaMA、Qwen）通常只发布到 SFT 阶段，部分提供 RLHF/DPO 版本。这意味着开源模型在「听话程度」和「安全性」上可能略逊于闭源旗舰，但在事实知识和推理能力上差距正在快速缩小。

LLM 的能力边界

了解 LLM 能做什么、不能做什么，比盲目追求最新模型更重要。

LLM 擅长的任务

  • 文本生成与改写——写作、翻译、摘要、风格转换
  • 知识问答——基于训练数据中的事实回答问题（注意：可能有幻觉）
  • 代码生成与调试——根据描述生成代码、解释代码、定位 bug
  • 结构化数据提取——从非结构化文本中提取 JSON、表格等结构化信息
  • 创意写作——故事、诗歌、广告文案等
  • 逻辑推理（有限）——数学题、逻辑谜题（大模型表现更好）

LLM 的局限

  • 幻觉（Hallucination）——LLM 可能生成看似合理但实际错误的信息。这是 LLM 最核心的局限，因为模型本质上是在做概率预测，而非检索事实。对于关键信息（如医疗、法律、财务），必须人工核实
  • 知识截止——模型的训练数据有截止日期，之后的事件和知识模型不知道（除非通过 RAG 或工具调用补充）
  • 数学和精确计算——LLM 不擅长精确的数学计算（尤其是多位数运算），更适合概念性数学推理。需要精确计算时应调用外部工具
  • 长程一致性——在超长文本生成中，模型可能忘记前文的设定或产生自相矛盾的内容
  • 真实世界理解——LLM 没有物理世界的直接经验，对空间关系、物理规律的理解来自文本描述，可能不准确
  • 时效性——无法获取实时信息（新闻、股价、天气等），需要配合搜索工具使用
实用建议：将 LLM 视为一个「知识渊博但偶尔会犯错的助手」，而非绝对权威。对于重要决策，始终交叉验证模型输出的信息。善用 LLM 擅长的领域（创意、草稿、结构化），避免过度依赖其不擅长的领域（精确计算、实时信息、专业判断）。
