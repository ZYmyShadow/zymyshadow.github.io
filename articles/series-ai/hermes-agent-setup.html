从零到一搭建 Hermes Agent：一个IT人的真实踩坑记录

摘要：写给想尝试 Hermes Agent 但被安装配置劝退的人。本文把从零搭建到跑通的完整流程走一遍，标出每个坑的位置和解法。读完能得到一份可照着操作的搭建指南，知道哪里会出问题、出了问题怎么修。

一、引言：为什么我决定试试 Hermes Agent

2026 年开源 AI Agent 领域有两个明星项目：OpenClaw（龙虾）和 Hermes Agent（爱马仕）。龙虾主打多平台连接，Hermes 主打自进化——越用越聪明。

作为修仙藏书阁的宗主，我每天用各种 AI 工具干苦力活。龙虾我已经用了一段时间，但它有个让我头疼的问题：记不住事。每次对话都得重新交代背景，同样的配置反复说明，复杂操作流程用完就丢，没法复用。

Hermes Agent 的卖点正好戳中我的痛点：三层持久记忆（简单说就是它真的能记住你之前聊过什么、你的偏好是什么），跨会话记住你的偏好和项目背景。再加上技能自动沉淀——完成复杂任务后自动把流程提炼成可复用的「技能」，下次遇到类似任务直接调用，不用从头教。这是龙虾做不到的。

于是我在一个周末下午，决定从零搭建 Hermes Agent。以下是真实过程，包括踩过的每一个坑。

太长不看
如果你不想折腾命令行和配置文件，可以直接跳到第七节「不想折腾？试试桌面版」，用 Hermes Agent CN Desktop 图形界面版，像装微信一样装好，5 分钟上手。本文的踩坑记录主要写给愿意深入了解、或者正在踩坑的人。

二、环境准备：看似简单，暗藏第一个坑

核心观点
Hermes Agent 官方支持 macOS、Linux 和 Windows（WSL2），Windows 原生 PowerShell 是 Beta 版。如果你用 Windows，老老实实上 WSL2，别侥幸用 PowerShell。

Hermes Agent 的系统要求：

  • 基础依赖：Git（必需）、Python 3.11（自动安装）、Node.js v22（自动安装）
  • Windows 用户需要 WSL2，原生 PowerShell 为 Beta 版

第一个坑就在这里。我用的是 Windows，一开始想着「Beta 版应该也能用吧」，直接用 PowerShell 跑安装脚本。结果安装过程报了一堆路径和权限错误，折腾了半小时没搞定。

实例
我在 PowerShell 里跑 irm https://res1.hermesagent.org.cn/install.ps1 | iex，安装到一半报了个 Node.js 路径找不到的错误。查了半天发现是 PowerShell 的环境变量处理和 Unix-like 系统不一样，导致自动安装 Node.js 的脚本没正确设置路径。

解决方案很直接：装 WSL2。如果你还没装，在 PowerShell（管理员）里执行 wsl --install，重启后在 WSL2 的 Ubuntu 终端里操作就行。别走我的弯路。

安装前检查命令：

git --version  # 需输出 2.0+ 版本

确认 Git 可用后，进入下一步。

三、安装：一键脚本的顺利与意外

WSL2 环境下，安装其实很丝滑。执行一键安装命令（国内镜像加速）：

curl -fsSL https://res1.hermesagent.org.cn/install.sh | bash

脚本会自动下载 Hermes Agent 并安装依赖（Python 3.11、Node.js v22），国内镜像加速，下载速度不错。安装完成后刷新环境变量：

source ~/.bashrc

然后验证：

hermes --version
hermes doctor

hermes doctor 会检查环境依赖、模型配置、工具可用性等，类似一个健康检测。如果全部通过，恭喜你，安装阶段没坑。

但第二个坑来了：hermes: command not found。

补充说明
这个问题是因为安装脚本把 hermes 命令装到了 ~/.local/bin，但你的 shell 配置文件可能没有把这个路径加入 PATH。解决方法：在 ~/.bashrc（或 ~/.zshrc）末尾添加 export PATH="$HOME/.local/bin:$PATH"，然后 source ~/.bashrc 生效。

我在这里卡了一小会儿，但解决起来不难。过了这关，安装就算完成了。

四、模型接入：踩坑最多的环节

核心观点
模型接入是整个搭建过程中坑最多的环节。核心问题是 API 地址格式——有些中转服务的地址需要带 /v1，有些不需要，试错成本不低。

Hermes Agent 支持 200+ 模型，配置命令是：

hermes model

简单说，这一步就是告诉 Hermes Agent 用哪个 AI 大脑来工作。你可以选国内的（智谱、Kimi、通义千问），也可以选国外的（OpenAI、Claude），甚至可以用本地部署的模型。

支持国内外主流模型：

类型 提供商 环境变量
国内智谱 GLMZHIPUAI_API_KEY
国内Kimi（月之暗面）KIMI_API_KEY
国内阿里云通义千问DASHSCOPE_API_KEY
国外OpenAIOPENAI_API_KEY
国外Anthropic ClaudeANTHROPIC_API_KEY
中转OpenRouterOPENROUTER_API_KEY
本地OllamaCustom Endpoint

所有配置集中在 ~/.hermes/ 目录：config.yaml 是主配置，.env 存储 API Key（权限自动设为 600）。

我选了 OpenRouter 接入，因为它一个 Key 能访问多个模型，不用每个提供商单独注册。

第三个坑：API 连接失败。配置完 Key 和 Base URL 后，第一次对话报连接错误。

实例
我的 Base URL 一开始填的是 https://openrouter.ai/api/v1，结果报连接超时。查了社区论坛发现，Hermes 在某些中转服务上对 URL 格式有要求——有时候需要带 /v1，有时候不能带。我把地址改成 https://openrouter.ai/api（去掉 /v1）后重启 Hermes，就通了。这个问题的根因个人体感是 Hermes 内部的 API 客户端在不同版本对 URL 拼接逻辑有差异，具体表现因提供商而异。

解决方案：如果带 /v1 不行就去掉，去掉不行就加上，改完务必重启 Hermes。这不是优雅的解法，但目前最有效。

第四个坑：模型切换后旧配置残留。通过 hermes model 切换模型后，有时候旧的 API Key 还在 .env 里生效，导致请求发到了错误的提供商。解决方法：手动编辑 ~/.hermes/.env，把不用的 Key 注释掉或删除，然后重启。

五、Profile 创建：新身份加载不出来的灵异事件

模型跑通后，我开始创建 Profile。Hermes 的 Profile 机制是每个身份独立——记忆、技能、配置互不干扰，相当于多个专属助理。

创建方式：

hermes profile create analyst --clone

--clone 会从现有 Profile 复制设置作为起点，不加 --clone 则从空白开始。

第五个坑：新建的 Profile 没有被加载。创建完之后切换到新 Profile，发现它的记忆是空的，之前克隆的设置没带过来。

注意事项
创建新的 Profile 后，务必重启 Hermes。这是已知问题——新 Profile 创建后可能不会被立即加载，重启后才能正常使用。我在这个坑上浪费了二十分钟，以为是自己操作有误，反复删除重建了好几次，最后发现只要重启就好了。

这个问题的根因个人体感是 Hermes 的 Profile 加载机制在运行时不会热刷新，需要重启进程才能读取新的 Profile 配置。希望后续版本能修复。

六、进阶尝试：Docker 部署与 MCP 集成

补充说明
这一节是进阶内容，如果你只是想日常用 Hermes Agent 聊天、管任务，可以跳过。Docker 和 MCP 是给需要长期稳定运行、或者想连接外部工具（比如 GitHub）的人准备的。

基础功能跑通后，我尝试了两个进阶玩法。

Docker 沙箱部署：

mkdir -p ~/.hermes
docker run -it --rm -v ~/.hermes:/opt/data nousresearch/hermes setup

docker run -d \
  --name hermes \
  --restart unless-stopped \
  -v ~/.hermes:/opt/data \
  nousresearch/hermes gateway run

Docker 部署的好处是隔离——工具执行不会影响宿主机，适合长期运行和生产环境。我这边跑得比较顺，没有遇到额外坑。唯一注意的是第一次 setup 要用 -it 交互模式完成初始化，之后再 run 守护进程。

MCP 集成（连接 GitHub）：

编辑 ~/.hermes/config.yaml，添加 MCP 服务器配置：

mcp_servers:
  github:
    command: npx
    args: ["-y", "@modelcontextprotocol/server-github"]
    env:
      GITHUB_PERSONAL_ACCESS_TOKEN: "你的令牌"

第六个坑：MCP 服务器启动失败。原因是 npx 需要 Node.js 环境，而 Docker 容器内的 Node.js 版本和宿主机不一致。解决方案：在 Docker 部署时确保容器内 Node.js 版本不低于 v22，或者在宿主机直接运行（不用 Docker）。

七、不想折腾？试试桌面版

核心观点
如果你看到这里觉得「这也太麻烦了」，别灰心。Hermes Agent 有桌面版，不需要碰一行命令，像装普通软件一样就能用。

上面这些坑，基本都是命令行版本带来的。如果你不想折腾终端、环境变量、配置文件，可以直接用 Hermes Agent 的桌面版。

目前桌面版有两个选择：

官方桌面版：在 Hermes Agent 官网（hermes-agent.nousresearch.com）下载安装包，macOS 拖进 Applications，Windows 双击安装，跟装微信一样简单。装好后首次启动会自动配置后台环境，等进度条走完就能用。界面默认英文，在设置里切换成简体中文即可。

中文社区增强版（CN Desktop）：由社区开发者在官方基础上做了增强，功能更全、稳定性更好，对国内用户更友好。安装方式同样是下载安装包双击运行，启动后选择 Local（本地模式），软件会自动检测并安装 Hermes Agent 核心程序、Python 及所有依赖——全程不需要你手动敲任何命令。装好后只需在设置里填入模型 API Key 就能开始使用。

实例
我后来把书房的备用电脑装了桌面版试试，从下载到第一次对话成功，总共花了不到 5 分钟。对比命令行版本折腾了 3 小时，体验差距非常明显。桌面版的功能和命令行版基本一致——对话、技能、会话管理、Profile 创建都有，只是换了个图形界面。对大多数非技术用户来说，桌面版完全够用。

当然，桌面版也有自己的小问题。比如 macOS 首次打开可能提示「无法验证开发者」，需要在系统设置里手动允许。Windows 可能弹出「未知发布者」安全提示，点「更多信息」再点「仍要运行」就行。这些都是系统安全机制，不是软件本身的问题。

简单总结一下两种路线的选择：

你的情况推荐方案
想快速体验，不想碰命令行桌面版（官方或 CN Desktop）
用 macOS / Linux，喜欢终端命令行一键脚本安装
想深度定制、长期运行命令行 + Docker 部署
用 Windows，不想装 WSL2桌面版（避开 WSL2 的坑）

八、结语：值不值得花这个时间

先说结论：值得，但要做好踩坑的心理准备。

Hermes Agent 的核心价值在于「越用越聪明」——三层持久记忆让它在跨会话时确实能记住你的上下文，技能自动沉淀让重复任务越来越高效。这些能力是 OpenClaw 和其他同类工具不具备的。

但搭建过程不算顺畅。我从一个下午的时间投入来看，大约花了 3 小时从零到跑通，其中一半时间在踩坑和查解决方案。如果你用 macOS 或 Linux，坑会少很多；Windows 用户务必走 WSL2 路线。

当然，如果你只是想体验 Hermes Agent 的能力，不想花时间踩坑，直接用桌面版——官方桌面版或中文社区增强版都行，5 分钟装好就能用。命令行版本适合喜欢折腾、想深度定制的人；桌面版适合想快速上手、专注使用的人。两条路，选适合自己的就好。
